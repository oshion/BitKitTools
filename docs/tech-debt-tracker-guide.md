# tech-debt-tracker.md 작성 가이드

> 이 파일은 가이드입니다. 실제 프로젝트 시작 시 `docs/tech-debt-tracker.md`를 새로 만들어서 사용하세요.

---

## 왜 인-레포 마크다운인가

git 히스토리도 기술 부채를 추적하지만, **에이전트는 git log를 맥락으로 읽지 않는다.**
에이전트가 새 세션에서 코드를 작성할 때 "현재 알려진 문제"를 인식하려면
리포지터리 안에 마크다운으로 남아있어야 한다.

> Harness Engineering 아티클:
> "에이전트의 관점에서 보면 실행 중에 컨텍스트 내에서 액세스할 수 없는 것은 사실상 존재하지 않는 것."

---

## 실제 프로젝트에서 만들 파일: `docs/tech-debt-tracker.md`

### 형식

```markdown
# Tech Debt Tracker

## 활성 부채

| ID | 영역 | 내용 | 심각도 | 발견일 |
|----|------|------|--------|--------|
| TD-001 | lib/api/ | 에러 처리 없이 fetch 그냥 throw | 중 | 2025-01-10 |
| TD-002 | components/ | any 타입 임시 사용 (Button.tsx:32) | 높음 | 2025-01-12 |

## 해결된 부채

| ID | 내용 | 해결일 | PR |
|----|------|--------|----|
| TD-000 | 예시 항목 | 2025-01-09 | #12 |
```

### 심각도 기준

| 심각도 | 기준 |
|--------|------|
| 높음 | 버그 유발 가능, 보안 문제, 타입 안전성 훼손 |
| 중 | 코드 냄새, 중복, 레이어 규칙 임시 우회 |
| 낮음 | 리팩터링 필요하지만 동작에 영향 없음 |

---

## 에이전트가 이 파일을 읽는 시점

- `execute.py`가 `docs/**/*.md`를 가드레일로 주입하므로 **매 step마다 자동으로 읽힌다.**
- `/harness` 실행 시 탐색 단계에서 읽힌다.
- `/review` 실행 시 체크리스트 판단 근거로 사용된다.

---

## 관리 원칙

1. 부채 발생 즉시 기록한다. 나중에 기억에 의존하지 않는다.
2. 해결되면 "해결된 부채" 섹션으로 이동한다. 삭제하지 않는다.
3. "높음" 부채가 3개 이상이면 다음 phase 시작 전에 해소한다.
